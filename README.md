# Employee Attendance & Analytics API

A REST API built with **FastAPI** and **MongoDB** for managing employee records, recording attendance, and retrieving attendance analytics.

## Features

- Create and list employees.
- Record employee punch-in and punch-out events.
- List attendance records and correct attendance entries.
- Generate monthly employee attendance analytics.
- View department-level attendance summaries and trends.
- Retrieve a late-arrival leaderboard.
- Inspect query plans through admin explain endpoints.
- Create MongoDB indexes at application startup to support common queries.
- Use API documentation generated by FastAPI.

## Tech Stack

- **Python**
- **FastAPI**
- **PyMongo**
- **MongoDB**
- **Pydantic**
- **Uvicorn**
- **python-dotenv**

## Prerequisites

- Python 3.10 or newer
- A running MongoDB instance or MongoDB Atlas cluster
- `pip`

## Getting Started

### 1. Clone the repository

```bash
git clone <repository-url>
cd <repository-directory>
```

Replace the placeholders with your repository URL and directory name.

### 2. Create and activate a virtual environment

**Windows PowerShell**

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

**macOS / Linux**

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Install dependencies

```bash
python -m pip install -r requirements.txt
```

### 4. Configure environment variables

Create a local `.env` file if the application uses environment variables. Set the MongoDB connection details and database settings using the **exact variable names expected by `app/main.py`**.

Do not commit `.env` files, database passwords, or other secrets to version control. Keep a `.env.example` file with placeholder values if you want to document the required configuration.

### 5. Start the API

From the repository root, run:

```bash
uvicorn app.main:app --reload
```

This command assumes the FastAPI instance is named `app` in `app/main.py`. If your module or instance name differs, update the command accordingly.

## API Documentation

Once the server is running, open:

- **Swagger UI:** `http://127.0.0.1:8000/docs`
- **ReDoc:** `http://127.0.0.1:8000/redoc`
- **Health check:** `http://127.0.0.1:8000/health`

## API Endpoints

The following endpoints are part of the API. Check the route definitions and request models in `app/main.py` for required parameters and payload schemas.

| Method | Endpoint | Purpose |
|---|---|---|
| `GET` | `/health` | Check API health |
| `POST` | `/employees` | Create an employee |
| `GET` | `/employees` | List employees |
| `POST` | `/attendance/punch-in` | Record an employee punch-in |
| `POST` | `/attendance/punch-out` | Record an employee punch-out |
| `GET` | `/attendance` | List attendance records |
| `PATCH` | `/attendance/{emp_code}/{date}` | Update an attendance record |
| `GET` | `/analytics/employees/{emp_code}/monthly` | Retrieve monthly employee analytics |
| `GET` | `/analytics/departments/summary` | Retrieve department attendance summaries |
| `GET` | `/analytics/leaderboard/late` | Retrieve the late-arrival leaderboard |
| `GET` | `/analytics/departments/{department}/trend` | Retrieve a department attendance trend |
| `GET` | `/admin/explain/{endpoint}` | Inspect a query plan for a supported endpoint |

Some endpoints may require query parameters or request bodies. Refer to `/docs` for the exact schemas and available options.

## MongoDB Indexes and Concurrency

The application creates indexes during startup to support its main query patterns and enforce data integrity. In particular, unique indexes can prevent duplicate employee codes and duplicate attendance records for the same employee and date.

Attendance write operations should be tested under concurrent requests to verify that duplicate or conflicting operations are handled as expected.
